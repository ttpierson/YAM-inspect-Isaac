# yam-sim-launchable

Bimanual [I2RT YAM](https://i2rt.com/products/yam-6-dof-arm) simulation for
[Isaac Lab](https://isaac-sim.github.io/IsaacLab/), packaged to become a Brev
launchable alongside [inspect-robots](https://github.com/robocurve/inspect-robots).

Status: the scene works (two arms, table, cube, plate, overhead and wrist cameras) and
runs under inspect-robots as the `yam_sim` embodiment. `launchable/setup.sh` builds the
whole workstation on a bare Brev GPU VM (see [Brev launchable](#brev-launchable)); it has
not yet been run end to end on a fresh instance.

## Layout

| Path | What |
|---|---|
| `assets/yam/` | YAM URDF + meshes vendored from [i2rt](https://github.com/i2rt-robotics/i2rt) (MIT, see `LICENSE.i2rt`, `SOURCE_COMMIT`) |
| `assets/yam/collision/` | Convex collision hulls per link, generated from the meshes by `scripts/make_collision_meshes.py` (CoACD) |
| `assets/yam/yam_sim.urdf` | Generated by `scripts/make_sim_urdf.py`: adds those hulls as the collision geometry upstream lacks |
| `yam_sim/assets.py` | `YAM_CFG`, one arm as an Isaac Lab `ArticulationCfg` |
| `yam_sim/scene.py` | `BimanualYamSceneCfg`, the tabletop scene |
| `yam_sim/cli.py` | The `yam-sim view` and `yam-sim edit` commands |
| `yam_sim/embodiment.py` | `yam_sim`, the scene as an inspect-robots embodiment |
| `launchable/setup.sh` | Brev setup script: Isaac Sim + Isaac Lab, inspect-robots, this repo, the browser desktop |
| `launchable/desktop.sh` | The browser desktop (Xvfb + xfce + noVNC on port 6080), run by the `yam-desktop` service |
| `scripts/view_scene.py` | Spawns the scene and runs a demo motion |
| `scripts/check_collision.py` | Measures, per link, how closely the simulated colliders follow the visual meshes |
| `arena/` | The same tabletop in Isaac Lab Arena: the `yam-arena` command and `yam_tabletop` embodiment, see [its README](arena/README.md) |

## Run

Inside an Isaac Lab 2.3 environment:

```bash
python scripts/view_scene.py                                   # GUI
python scripts/view_scene.py --headless --screenshots out/ --steps 600
```

Each arm exposes `joint1`-`joint6` plus the two finger joints `joint7`/`joint8`
(0 = closed, -0.04695 m = open). At zero joint angles the gripper points along +X.

## View and edit the scene

`pip install -e .` (see below) also installs a `yam-sim` command. Both subcommands open the
Isaac Sim GUI. Over ssh with no `DISPLAY`, they use the instance's noVNC desktop on `:1`.

```bash
yam-sim view                       # the built-in scene; the arms hold their ready pose
yam-sim view scenes/kitchen.usda   # a scene saved by `yam-sim edit`
yam-sim edit scenes/kitchen.usda   # opens the file if it exists, else the built-in scene
```

`edit` opens the scene with physics stopped and adds a "YAM scene" panel with Play,
Pause, Stop and Save buttons. Use the panel's buttons, not the toolbar's: Isaac Lab hides
the toolbar's Stop button, and its Play button while stopped. Edit with Isaac Sim's own tools: move prims with the gizmo, add shapes from
Create, drag assets in from the content browser, change lights and materials in the
Property panel. The arms stand frozen in their ready pose for reference (they collide
but don't move). To let objects settle onto the table, press Play, then Save (playing
or paused). Stop rewinds to where things were when you pressed Play. Edits made while
paused only reach physics after Stop and Play.

Under the hood, the editor hands the stage over to Isaac Sim once the arms are posed.
Editing a physics prim makes PhysX re-read the stage, which breaks Isaac Lab's physics
handles, so Isaac Lab doesn't drive anything while you edit.

Save writes the *environment* (everything except the two arms and the policy cameras,
which always come from `yam_sim/scene.py`) to the file. It is flattened, so assets
dragged in from a library are copied in rather than referenced. A stage saved with
Isaac Sim's File > Save As also loads; its arms and cameras are ignored. On load, every
free rigid body becomes a rigid object that resets to its saved pose.

## Inspect Robots

Install into the Isaac Lab environment. Use an editable install, because the URDF and
meshes are read from this checkout:

```bash
pip install -e .
inspect-robots list embodiments        # includes yam_sim
```

`yam_sim` has the same observation and action contract as the real rig's `yam_arms`
embodiment from [inspect-robots-yam](https://github.com/robocurve/inspect-robots-yam),
so policies written for the real arms (`molmoact2`, `gr00t`, `agent`) run against it
unchanged:

| | |
|---|---|
| Cameras | `top_cam` (overhead D435), `left_cam` and `right_cam` (D405 on each wrist), RGB 224x224 |
| State `joint_pos` | 14-D: `[left j0..j5, left gripper, right j0..j5, right gripper]`, joints in rad, grippers 0 closed to 1 open |
| Action | the same 14-D layout as absolute joint targets, at 10 Hz |

```bash
inspect-robots run --embodiment yam_sim --policy agent --instruction "put the red cube on the plate"
inspect-robots run --embodiment yam_sim -E headless=false ...   # render on DISPLAY (noVNC desktop)
```

On a machine set up for the real rig, make `yam_sim` its simulated counterpart so
`--sim` swaps it in for `yam_arms`. Add it to `[defaults]` in
`~/.config/inspect-robots/config.ini`:

```ini
[defaults]
embodiment = yam_arms
sim_embodiment = yam_sim
```

Other `-E` options: `scene` (a file from `yam-sim edit`), `cam_height`, `cam_width`,
`control_hz`, `device`. A seeded reset shifts every object (the cube and plate in the
built-in scene) by up to 3 cm.

## Brev launchable

`launchable/setup.sh` turns a bare Ubuntu GPU VM into this workstation:

- Isaac Sim 5.1 and Isaac Lab 2.3.2 in a uv venv (`env_isaaclab`, Python 3.11),
  activated in `~/.bashrc`
- [inspect-robots](https://github.com/robocurve/inspect-robots) (tag `v0.60.0`) with its
  `agent` policy plugin, and this repo, all editable (`source <prefix>/env_isaaclab/bin/activate`)
- in a second venv (`IsaacLab-Arena/.venv`, Python 3.12, with Isaac Sim 6 and Isaac Lab 3.0):
  [Isaac Lab Arena](https://github.com/isaac-sim/IsaacLab-Arena) 0.3.1,
  [yam-isaac-lab-arena](https://github.com/kairosiann/yam-isaac-lab-arena) (the `yam_arena`
  embodiment and `yam_scripted` demo policy),
  [Dream-1](https://github.com/kairosiann/inspect-robots-dream) (the `dream` policy), and this
  repo's [Arena tabletop](arena/README.md); the two kairosiann repos are pinned to commits.
  New shells start here
- a browser desktop as the `yam-desktop` systemd service: Xvfb + xfce on `:1`, noVNC on
  port 6080, password in `~/yam-desktop-password`
- the trial reports for `~/yam-eval` as the `yam-reports` systemd service, on port 8300
- one run of the scripted demo, so Isaac Sim's first start is out of the way and the reports
  have something to show; if it fails, setup warns and carries on

It installs under `/data` when that is writable, else `$HOME`, logs to `yam-setup.log`
there, and skips finished steps when re-run. The first run takes a while; most of it is
the Isaac Sim download.

Deploying it accepts the
[NVIDIA Omniverse license](https://docs.isaacsim.omniverse.nvidia.com/latest/common/NVIDIA_Omniverse_License_Agreement.html)
for Isaac Sim (it sets `OMNI_KIT_ACCEPT_EULA=YES`).

### Create the launchable

In the [Brev console](https://brev.nvidia.com), open **Launchables** and create one:

1. **Compute**: an L40S (any RTX GPU works; Isaac Sim needs RT cores, so not A100/H100),
   with about 200 GB of disk.
2. **Software**: VM mode, Ubuntu 22.04 with the NVIDIA driver.
3. **Code**: this repo, `https://github.com/ttpierson/YAM-inspect-Isaac`.
4. **Setup script**: the contents of `launchable/setup.sh`, or a line that fetches it:
   ```bash
   curl -fsSL https://raw.githubusercontent.com/ttpierson/YAM-inspect-Isaac/main/launchable/setup.sh | bash
   ```
5. **Network**: a secure link for port 6080, set as the CTA (the bare link opens the
   desktop), and a second secure link for port 8300 (the trial reports, which have no password).
   Don't also open either as a public TCP port: the VNC password is all that guards 6080. The
   desktop comes up only after setup finishes; Jupyter (8888), if installed, is up sooner
   and handy for watching `yam-setup.log`.

### Use it

Once the setup log ends with `=== [yam-setup] done`, open the 6080 link (or run
`brev port-forward <instance> -p 6080:6080` and open http://localhost:6080/vnc.html), and
log in with the password from `~/yam-desktop-password`. From a terminal on the desktop or
over `brev shell`:

```bash
# The scripted demo in Dream's station scene, which reaches full score
inspect-robots run --embodiment yam_arena --policy yam_scripted \
  -E scene=station -E object_jitter=0 -E control_hz=20 -E cam_width=320 -E cam_height=176 \
  --instruction "put apple into the bowl" --scorer success_at_end \
  --max-steps 600 --store-frames --log-dir ~/yam-eval

# Dream-1, with a key from https://platform.dreamlabs.ai/api-keys
mkdir -p ~/.dreamlabs && echo 'DREAM_API_KEY=dl_live_...' > ~/.dreamlabs/credentials
chmod 600 ~/.dreamlabs/credentials
inspect-robots run --embodiment yam_arena --policy dream \
  -E scene=station -E object_jitter=0 -E control_hz=20 -E cam_width=320 -E cam_height=176 \
  --instruction "put apple into the bowl" --scorer success_at_end \
  --max-steps 2400 --store-frames --log-dir ~/yam-eval

# Your own task: edit ~/my_task.py (a copy of examples/stack_cubes.py), then use
#   -E task=~/my_task.py --instruction "put the red cube on the blue block" --scorer task_score

# One MP4 per camera, in ~/yam-eval/frames/<run>/
for log in ~/yam-eval/*.json; do inspect-robots video "$log"; done

# Your Arena tabletop scene
yam-arena view
yam-arena eval arena/experiments/yam_tabletop.yaml
```

Open the 8300 link to browse the reports; a run in `~/yam-eval` appears there by itself. Add
`-E headless=false` to a run and its window opens on the desktop, also from `brev shell`. See the
[yam-isaac-lab-arena README](https://github.com/kairosiann/yam-isaac-lab-arena) for its scenes,
task files and policies; skip its `setup.sh --desktop`, because `yam-desktop` already holds
display `:1` and port 6080.

For Isaac Lab, `source <prefix>/env_isaaclab/bin/activate`, then:

```bash
yam-sim view                    # the scene, arms holding still
yam-sim edit ~/scene.usda       # edit and save the environment
export ANTHROPIC_API_KEY=...    # for the agent policy
inspect-robots run --embodiment yam_sim --policy agent --instruction "put the red cube on the plate"
```

`sudo systemctl restart yam-reports` restarts the reports. `sudo systemctl restart yam-desktop` restarts the desktop if it gets stuck.
