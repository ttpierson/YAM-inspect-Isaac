# yam-sim-launchable

Bimanual [I2RT YAM](https://i2rt.com/products/yam-6-dof-arm) simulation for
[Isaac Lab](https://isaac-sim.github.io/IsaacLab/), packaged to become a Brev
launchable alongside [inspect-robots](https://github.com/robocurve/inspect-robots).

Status: the scene works (two arms, table, cube, plate, overhead and wrist cameras) and
runs under inspect-robots as the `yam_sim` embodiment. The launchable setup script
comes next.

## Layout

| Path | What |
|---|---|
| `assets/yam/` | YAM URDF + meshes vendored from [i2rt](https://github.com/i2rt-robotics/i2rt) (MIT, see `LICENSE.i2rt`, `SOURCE_COMMIT`) |
| `assets/yam/collision/` | Convex collision hulls per link, generated from the meshes by `scripts/make_collision_meshes.py` (CoACD) |
| `assets/yam/yam_sim.urdf` | Generated by `scripts/make_sim_urdf.py`: adds those hulls as the collision geometry upstream lacks |
| `yam_sim/assets.py` | `YAM_CFG`, one arm as an Isaac Lab `ArticulationCfg` |
| `yam_sim/scene.py` | `BimanualYamSceneCfg`, the tabletop scene |
| `yam_sim/cli.py` | The `yam-sim view` and `yam-sim edit` commands |
| `yam_sim/embodiment.py` | `yam_sim`, the scene as an inspect-robots embodiment |
| `scripts/view_scene.py` | Spawns the scene and runs a demo motion |
| `scripts/check_collision.py` | Measures, per link, how closely the simulated colliders follow the visual meshes |

## Run

Inside an Isaac Lab 2.3 environment:

```bash
python scripts/view_scene.py                                   # GUI
python scripts/view_scene.py --headless --screenshots out/ --steps 600
```

Each arm exposes `joint1`-`joint6` plus the two finger joints `joint7`/`joint8`
(0 = closed, -0.04695 m = open). At zero joint angles the gripper points along +X.

## View and edit the scene

`pip install -e .` (see below) also installs a `yam-sim` command. Both subcommands open the
Isaac Sim GUI. Over ssh with no `DISPLAY`, they use the instance's noVNC desktop on `:1`.

```bash
yam-sim view                       # the built-in scene; the arms hold their ready pose
yam-sim view scenes/kitchen.usda   # a scene saved by `yam-sim edit`
yam-sim edit scenes/kitchen.usda   # opens the file if it exists, else the built-in scene
```

`edit` opens the scene with physics stopped and adds a "YAM scene" panel with Play,
Pause, Stop and Save buttons. Use the panel's buttons, not the toolbar's: Isaac Lab hides
the toolbar's Stop button, and its Play button while stopped. Edit with Isaac Sim's own tools: move prims with the gizmo, add shapes from
Create, drag assets in from the content browser, change lights and materials in the
Property panel. The arms stand frozen in their ready pose for reference (they collide
but don't move). To let objects settle onto the table, press Play, then Save (playing
or paused). Stop rewinds to where things were when you pressed Play. Edits made while
paused only reach physics after Stop and Play.

Under the hood, the editor hands the stage over to Isaac Sim once the arms are posed.
Editing a physics prim makes PhysX re-read the stage, which breaks Isaac Lab's physics
handles, so Isaac Lab doesn't drive anything while you edit.

Save writes the *environment* (everything except the two arms and the policy cameras,
which always come from `yam_sim/scene.py`) to the file. It is flattened, so assets
dragged in from a library are copied in rather than referenced. A stage saved with
Isaac Sim's File > Save As also loads; its arms and cameras are ignored. On load, every
free rigid body becomes a rigid object that resets to its saved pose.

## Inspect Robots

Install into the Isaac Lab environment. Use an editable install, because the URDF and
meshes are read from this checkout:

```bash
pip install -e .
inspect-robots list embodiments        # includes yam_sim
```

`yam_sim` has the same observation and action contract as the real rig's `yam_arms`
embodiment from [inspect-robots-yam](https://github.com/robocurve/inspect-robots-yam),
so policies written for the real arms (`molmoact2`, `gr00t`, `agent`) run against it
unchanged:

| | |
|---|---|
| Cameras | `top_cam` (overhead D435), `left_cam` and `right_cam` (D405 on each wrist), RGB 224x224 |
| State `joint_pos` | 14-D: `[left j0..j5, left gripper, right j0..j5, right gripper]`, joints in rad, grippers 0 closed to 1 open |
| Action | the same 14-D layout as absolute joint targets, at 10 Hz |

```bash
inspect-robots run --embodiment yam_sim --policy agent --instruction "put the red cube on the plate"
inspect-robots run --embodiment yam_sim -E headless=false ...   # render on DISPLAY (noVNC desktop)
```

On a machine set up for the real rig, make `yam_sim` its simulated counterpart so
`--sim` swaps it in for `yam_arms`. Add it to `[defaults]` in
`~/.config/inspect-robots/config.ini`:

```ini
[defaults]
embodiment = yam_arms
sim_embodiment = yam_sim
```

Other `-E` options: `scene` (a file from `yam-sim edit`), `cam_height`, `cam_width`,
`control_hz`, `device`. A seeded reset shifts every object (the cube and plate in the
built-in scene) by up to 3 cm.
